# Product Requirements Document (PRD): ระบบจัดเก็บไฟล์ประกาศขึ้น Google Drive อัตโนมัติ, สารบัญค้นหา และลิงก์คอมเมนต์แรก Facebook

---

## 1. Executive Summary

ผู้ดูแลงานประกาศรับสมัครงานและประชาสัมพันธ์ต้องเสียเวลาทำซ้ำหลายขั้นตอนในทุกประกาศ ได้แก่ การเปิดคลิกเข้าโฟลเดอร์ Google Drive หลายชั้น (`ประเภทพนักงาน` → `ขั้นตอน`), การตั้งชื่อไฟล์ตามรูปแบบวันที่, การเปิดสิทธิ์แชร์สาธารณะ และการคัดลอกลิงก์มาวางในคอมเมนต์แรกของ Facebook ด้วยตนเอง ฟีเจอร์นี้จะผสาน **Google Drive API (OAuth 2.0)** เข้ากับระบบ **Poster** โดยตรง เพื่อให้ผู้ใช้สามารถจัดเก็บไฟล์ PDF เข้าโฟลเดอร์ย่อยที่ถูกต้อง ตั้งชื่อไฟล์ตามสูตรมาตรฐาน เปิดสิทธิ์แชร์ นำลิงก์ Google Drive ไปใช้เป็นลิงก์หลักในคอมเมนต์แรกของ Facebook และปุ่มดาวน์โหลดบน WordPress (โดยคง PDF Viewer บนหน้าเว็บ WordPress เดิมไว้) รวมถึงค้นหาย้อนหลังและอัปโหลดไฟล์เก็บเข้าสารบัญได้จากหน้าจอเดียว

## 2. Goals & Success Metrics

| เป้าหมาย (Goal) | ตัวชี้วัดความสำเร็จ (Success Metric) |
| :--- | :--- |
| **ลดขั้นตอนการทำงานซ้ำซ้อน (Zero-Manual Drive & Commenting)** | ผู้ใช้สามารถแนบไฟล์ PDF เลือกหมวดหมู่ และกดเผยแพร่เพียงครั้งเดียว ระบบอัปโหลดเข้า Google Drive และยิงคอมเมนต์แรกบน Facebook พร้อมลิงก์ Drive อัตโนมัติ 100% |
| **ความสม่ำเสมอของโครงสร้างโฟลเดอร์และชื่อไฟล์** | ไฟล์ทุกฉบับถูกจัดเข้าโฟลเดอร์ `{ประเภทพนักงาน}/{ขั้นตอน}` และตั้งชื่อตามสูตร `YYYY-MM-DD {ขั้นตอน}-{ประเภทพนักงาน}-{รายละเอียด}.pdf` (เช่น `2026-10-26 รับสมัคร-รายวัน-แม่บ้าน.pdf`) โดยไม่สร้างโฟลเดอร์ซ้ำซ้อน |
| **รองรับบัญชี Google Workspace องค์กร (`My Drive`)** | เชื่อมต่อผ่าน OAuth 2.0 User Authorization ที่ใช้โควตาพื้นที่ของบัญชีองค์กรผู้ใช้ได้โดยไม่ติดข้อจำกัด 0-byte quota ของ Service Account |
| **ค้นหาและใช้งานแบบ Standalone ได้** | ผู้ใช้สามารถอัปโหลดไฟล์ประกาศเก็บขึ้น Google Drive อย่างเดียว (โดยไม่ต้องสร้างโพสต์โซเชียล) และค้นหา/คัดลอกลิงก์ย้อนหลังในหน้า **สารบัญประกาศ** ได้ภายในไม่เกิน 3 วินาที |
| **ไม่กระทบเสถียรภาพระบบเดิม (Zero Regression)** | ฟีเจอร์ Embedded PDF Viewer (`<iframe>`) บน WordPress, ระบบเผยแพร่ Facebook Graph API แบบเดิม และชุดทดสอบอัตโนมัติเดิมทั้งหมดยังทำงานได้ครบ 100% |

## 3. Non-Goals (Out of Scope)

รายการความสามารถที่ตั้งใจ **ไม่รวม** ในขอบเขต MVP รอบนี้ (Shape Up No-Gos):

1. **Two-Way Sync จากฝั่ง Google Drive กลับมายัง Poster:** ไม่มีการดึงไฟล์ย้อนหลังหรือจับ Webhook เมื่อมีคนไปลบ/ย้ายไฟล์ด้วยมือในหน้าเว็บ Google Drive โดยตรง (Poster ทำหน้าที่เป็นต้นทางจัดเก็บและทำสารบัญ)
2. **การใช้ Service Account อัปโหลดเข้า Personal/Workspace My Drive โดยไม่มี OAuth:** ไม่ใช้ Service Account เป็นกลไกหลักเนื่องจาก Google จำกัดพื้นที่จัดเก็บของ Service Account เป็น 0 bytes บน My Drive
3. **การถอดหรือแทนที่ WordPress Embedded PDF Viewer เดิม:** จะไม่เปลี่ยน `<iframe>` PDF Viewer บน WordPress ไปใช้ Google Drive iframe เพื่อป้องกันปัญหา X-Frame-Options/CSP บนเบราว์เซอร์ผู้เข้าชม (ยังคงอัปโหลด PDF เข้า WordPress Media สำหรับตัวอ่านหน้าเว็บตามเดิม แต่ปุ่มลิงก์เอกสารหลักทั้งหมดจะชี้ไปที่ Google Drive)
4. **การแก้ไขโครงสร้าง API หลักในการโพสต์รูป Facebook:** ไม่เปลี่ยนแปลงลำดับการอัปโหลดรูปและโพสต์ Feed ของ `FacebookPublisher` ตามข้อกำหนดใน `FACEBOOK_REACH_PLAN.md`
5. **การแก้ไขข้อความคอมเมนต์ Facebook ย้อนหลัง:** สำหรับโพสต์ Facebook ที่เผยแพร่ไปแล้ว ระบบจะไม่ตามไปแก้ไขคอมเมนต์เดิมย้อนหลัง (สอดคล้องกับข้อจำกัดของ Graph API และระบบ Replacement เดิมของ Poster)

## 4. User Stories & Edge Cases

### US-01: เชื่อมต่อบัญชี Google Drive ขององค์กรและตรวจสอบโครงสร้างโฟลเดอร์
* **Given** ผู้ใช้เข้าสู่หน้า `การเชื่อมต่อ (Settings > Integrations)` และกรอก Google OAuth Client ID, Client Secret พร้อมวางลิงก์หรือ ID ของโฟลเดอร์หลัก (Root Folder)
* **When** ผู้ใช้กดปุ่ม `"เชื่อมต่อบัญชี Google Drive"` และยืนยันสิทธิ์ผ่านบัญชีองค์กร (`@...ac.th`)
* **Then** ระบบเข้ารหัสและจัดเก็บ `refresh_token` ลงในตาราง `integration_settings`, แสดงอีเมลที่เชื่อมต่อสำเร็จ และสามารถกด `"ตรวจสอบโครงสร้างโฟลเดอร์"` เพื่อจับคู่โฟลเดอร์เดิมทั้ง 4 ประเภทพนักงาน × 3 ขั้นตอน (หรือสร้างโฟลเดอร์ที่ยังขาดให้อัตโนมัติ)

### US-02: สร้างโพสต์ข่าวพร้อมจัดเก็บ PDF ขึ้น Google Drive และใส่ลิงก์ใน Comment แรกอัตโนมัติ
* **Given** บัญชี Google Drive เชื่อมต่อพร้อมใช้งาน และผู้ใช้อยู่ในหน้า `เขียนข่าวใหม่ (Posts > Create)` (ไม่ว่าจะเลือกเผยแพร่เฉพาะ Facebook, เฉพาะ WordPress หรือทั้งสองช่องทาง)
* **When** ผู้ใช้แนบไฟล์ PDF, เปิดใช้ `"จัดเก็บขึ้น Google Drive"`, เลือกประเภทพนักงาน = `รายวัน`, ขั้นตอน = `รับสมัคร`, วันที่ = `2026-10-26`, รายละเอียด/ตำแหน่ง = `แม่บ้าน` (ระบบสร้างชื่อไฟล์ `2026-10-26 รับสมัคร-รายวัน-แม่บ้าน.pdf` และใส่ `{drive_url}` ในช่อง Comment #1) แล้วกด `"เผยแพร่ทันที"`
* **Then** ระบบจะ:
  1. อัปโหลดไฟล์ PDF ไปยังโฟลเดอร์ `รายวัน/รับสมัคร/` ใน Google Drive
  2. เปิดสิทธิ์ไฟล์เป็น `"ทุกคนที่มีลิงก์สามารถดูได้" (Anyone with link: reader)`
  3. เผยแพร่บทความขึ้น WordPress โดยปุ่ม Action/ดาวน์โหลดชี้ไปที่ลิงก์ Google Drive และยังคงแสดง PDF Viewer (`<iframe>`) บนหน้าเว็บเหมือนเดิม
  4. เผยแพร่โพสต์ขึ้น Facebook และส่งคอมเมนต์แรก (`fb_comment`) ที่มีลิงก์ Google Drive จริงต่อท้ายโพสต์ทันที

### US-03: อัปโหลดประกาศเก็บลง Google Drive อย่างเดียว (Standalone) และค้นหาในสารบัญ
* **Given** ผู้ใช้มีไฟล์ประกาศที่ต้องการจัดเก็บลง Google Drive และรับลิงก์แชร์ แต่ไม่ต้องการโพสต์ลง Facebook หรือ WordPress
* **When** ผู้ใช้เข้าหน้า `สารบัญประกาศ (Drive)` กดอัปโหลดไฟล์ เลือกประเภทพนักงาน ขั้นตอน วันที่ และชื่อตำแหน่ง
* **Then** ระบบตั้งชื่อไฟล์ตามสูตร อัปโหลดเข้าโฟลเดอร์ย่อยใน Google Drive ปรับสิทธิ์แชร์ บันทึกลงตารางสารบัญใน Poster พร้อมปุ่ม `"คัดลอกลิงก์ Google Drive"` และปุ่ม `"นำไปสร้างโพสต์ข่าว"` ได้ทันที

### US-04: ปรับแก้ชื่อไฟล์ด้วยตนเองก่อนอัปโหลด
* **Given** ระบบสร้างชื่อไฟล์อัตโนมัติเป็น `2026-10-26 รับสมัคร-รายวัน-แม่บ้าน.pdf`
* **When** ผู้ใช้พิมพ์แก้ไขช่องชื่อไฟล์ปลายทางเป็น `2026-10-26 รับสมัคร-รายวัน-แม่บ้าน (ครั้งที่ 2).pdf`
* **Then** ระบบจะคงชื่อที่ผู้ใช้แก้ไขเองไว้ (ไม่เขียนทับเมื่อแก้ฟิลด์อื่น จนกว่าจะกดปุ่มรีเซ็ตตามสูตร) และใช้ชื่อไฟล์นั้นบันทึกขึ้น Google Drive พร้อมทำความสะอาดอักขระต้องห้าม (`/ \ : * ? " < > |`)

### Edge Cases & Failure Paths

* **EC-01 (Idempotency เมื่อกด Retry ช่องทางที่ล้มเหลว):**
  * **Given** โพสต์อัปโหลดไฟล์ PDF ขึ้น Google Drive สำเร็จแล้ว (`drive_file_id` ถูกบันทึกแล้ว) แต่การโพสต์ไปยัง Facebook ล้มเหลวชั่วคราว (เช่น HTTP 500 หรือ Timeout)
  * **When** ระบบ Auto-retry หรือผู้ใช้กดปุ่ม `"ลองใหม่ (Retry)"` ที่ช่องทาง Facebook
  * **Then** ระบบต้อง **ไม่อัปโหลดไฟล์ PDF ซ้ำ** ขึ้น Google Drive อีก แต่ต้องนำ `drive_web_view_link` เดิมที่บันทึกไว้แล้วมาแทนค่า `{drive_url}` / `{pdf_url}` ทันที

* **EC-02 (ป้องกันลิงก์เสียหรือ Placeholder หลุดออกสาธารณะเมื่อ Google Drive ล้มเหลว):**
  * **Given** โพสต์เปิดใช้งาน Google Drive Sync หรือมีตัวแปร `{drive_url}` อยู่ในข้อความ/คอมเมนต์ แต่การอัปโหลดขึ้น Google Drive ล้มเหลว (เช่น Refresh Token ถูกเพิกถอน หรือโฟลเดอร์ปลายทางถูกลบ)
  * **When** คิวงาน `PublishPostJob` ทำงาน
  * **Then** ระบบต้องหยุดการส่งข้อความที่มี `{drive_url}` ดิบไปยัง Facebook/WordPress, บันทึกเหตุการณ์ลง `PublishTimeline` และแสดงข้อความแจ้งเตือนภาษาไทยที่ชัดเจนเพื่อให้ผู้ใช้แก้ไขและกด Retry ได้

* **EC-03 (ความแตกต่างของการเว้นวรรคภาษาไทยในชื่อโฟลเดอร์เดิม เช่น `พนักงานอื่นๆ` vs `พนักงานอื่น ๆ`):**
  * **Given** ใน Google Drive เดิมของผู้ใช้มีโฟลเดอร์ชื่อ `พนักงานอื่น ๆ` (มีช่องว่างหน้าไม้ยมก) แต่ค่าตัวเลือกคือ `พนักงานอื่นๆ`
  * **When** ระบบค้นหาโฟลเดอร์ปลายทางภายใต้ Root Folder
  * **Then** ระบบเปรียบเทียบชื่อแบบ Exact Match ก่อน และหากไม่พบจะเปรียบเทียบแบบ Normalized Thai Spacing เพื่อใช้โฟลเดอร์เดิมที่มีอยู่แทนการสร้างโฟลเดอร์ซ้ำ

* **EC-04 (นโยบายองค์กรบล็อกการแชร์สาธารณะภายนอกโดเมน):**
  * **Given** ผู้ดูแล Google Workspace ของมหาวิทยาลัยตั้งนโยบายห้ามแชร์ไฟล์แบบ `type=anyone` นอกองค์กร
  * **When** ระบบเรียก API `permissions.create` แล้วได้รับ HTTP `403 Forbidden`
  * **Then** ระบบบันทึกสถานะสิทธิ์เป็น `restricted` และแจ้งเตือนข้อความภาษาไทยให้ผู้ใช้ทราบทันทีว่าไฟล์อัปโหลดแล้วแต่ติดนโยบายจำกัดสิทธิ์แชร์สาธารณะขององค์กร

## 5. Functional Requirements

### 5.1 โมดูลการตั้งค่าและเชื่อมต่อ (Google Drive Integration & OAuth 2.0)
* **FR-1.1:** เพิ่มช่องทาง `google_drive` ในตาราง `integration_settings` โดยเข้ารหัส `client_secret`, `refresh_token`, `access_token` ด้วย `encrypted:array` และซ่อนจากการ Serialize ทุกกรณี
* **FR-1.2:** รองรับการวางทั้ง **Google Drive Folder URL เต็ม** (เช่น `https://drive.google.com/drive/folders/1AbCdEf...`) หรือ **Folder ID** โดยระบบสกัด Folder ID ให้อัตโนมัติ
* **FR-1.3:** มี OAuth 2.0 Authorization Flow (`/settings/integrations/google-drive/redirect` และ `/callback`) ที่ตรวจสอบ `state` ป้องกัน CSRF และขอ `access_type=offline`, `prompt=consent`
* **FR-1.4:** ระบบต่ออายุ `access_token` อัตโนมัติผ่าน `refresh_token` ก่อนหมดอายุ 60 วินาที
* **FR-1.5:** มีฟังก์ชันตรวจสอบสถานะการเชื่อมต่อ (Health Check) และเครื่องมือตรวจสอบ/ซิงก์โฟลเดอร์ย่อย (เริ่มต้น 4 ประเภทพนักงาน: `รายวัน`, `พนักงานประจำตามสัญญา`, `พนักงานมหาวิทยาลัย`, `พนักงานอื่นๆ` และ 3 ขั้นตอน: `รับสมัคร`, `ประกาศรายชื่อ`, `ผลการคัดเลือก` โดยปรับเพิ่ม/ลดได้ในหน้าตั้งค่า)
* **FR-1.6:** อัปเดต `SecretSanitizer` ให้ปิดบัง `refresh_token`, `google_client_secret`, โทเคน `ya29.*` และ `1//*` ใน Log และ Exception ทุกจุด

### 5.2 โมดูลจัดการโฟลเดอร์ ตั้งชื่อไฟล์ และอัปโหลด (Drive Filing & Naming Engine)
* **FR-2.1:** สร้างชื่อไฟล์อัตโนมัติตามสูตร `YYYY-MM-DD {ขั้นตอน}-{ประเภทพนักงาน}-{รายละเอียด}.pdf` (ปี ค.ศ. 4 หลัก เช่น `2026-10-26 รับสมัคร-รายวัน-แม่บ้าน.pdf`) และตัดเครื่องหมาย `-` ท้ายชื่อออกอัตโนมัติหากไม่ได้กรอกรายละเอียดเพิ่มเติม
* **FR-2.2:** อัปโหลดไฟล์ผ่าน Google Drive REST API v3 (`uploadType=resumable`, `supportsAllDrives=true`) รองรับไฟล์ PDF ขนาดสูงสุด 20 MB ตามเพดานระบบเดิม
* **FR-2.3:** ตั้งค่าสิทธิ์ไฟล์เป็น `{"role": "reader", "type": "anyone"}` อัตโนมัติหลังอัปโหลด และจัดเก็บ `drive_file_id`, `drive_web_view_link` (`https://drive.google.com/file/d/{id}/view?usp=sharing`), `drive_folder_id`, `drive_folder_path` ลงฐานข้อมูล

### 5.3 โมดูลหน้าสร้าง/แก้ไขโพสต์ และเทมเพลต (Post & Template Editor)
* **FR-3.1:** ย้ายส่วนแนบไฟล์ประกาศ PDF ออกจากการซ่อนภายใต้เงื่อนไข `isWpSelected` มาเป็นการ์ดกลาง **"เอกสารประกาศ (PDF) & Google Drive"** เพื่อให้ใช้งานได้ทั้งกรณีโพสต์เฉพาะ Facebook, เฉพาะ WordPress หรือทั้งคู่
* **FR-3.2:** แสดงฟอร์มเลือก `ประเภทพนักงาน`, `ขั้นตอน`, `วันที่ประกาศ`, `ตำแหน่ง/รายละเอียด` และช่อง `ชื่อไฟล์ใน Google Drive` ที่แก้ไขเองได้ พร้อมรองรับระบบ Autosave Draft
* **FR-3.3:** เพิ่มตัวช่วยเติมลิงก์ `{drive_url}` ในช่อง **คอมเมนต์แรกของ Facebook (`fb_comment`)** อัตโนมัติเมื่อแนบไฟล์ประกาศ (ตั้งค่าข้อความนำหน้าเริ่มต้นในหน้า Settings ได้ เช่น `รายละเอียดประกาศฉบับเต็ม: {drive_url}`) พร้อมปุ่มกดแทรก `{drive_url}` ใน Comment #1, Comment #2 และ Action Buttons
* **FR-3.4:** เพิ่มฟิลด์ `fb_comment`, `drive_employee_category` และ `drive_announcement_stage` ในระบบ **Templates** เพื่อให้สร้างเทมเพลตแยกตามประเภทประกาศได้ครบวงจร
* **FR-3.5:** มีปุ่ม `"อัปโหลดรับลิงก์ Drive ทันที"` ในหน้าฟอร์มสร้างโพสต์ เผื่อกรณีต้องการได้ลิงก์จริงมาตรวจสอบหรือคัดลอกตั้งแต่สถานะฉบับร่าง (Draft)

### 5.4 โมดูลเผยแพร่และแทนค่าลิงก์ (Publishing Pipeline & Link Resolution)
* **FR-4.1:** ก่อนส่งงานไปยัง WordPress และ Facebook ระบบต้องตรวจสอบและซิงก์ไฟล์ PDF ขึ้น Google Drive ให้เสร็จสิ้นก่อน พร้อมบันทึก `PublishEvent` ลงใน Timeline
* **FR-4.2:** รองรับตัวแปร `{drive_url}` และ `{{drive_url}}` ในทุกช่องทาง และเมื่อไฟล์มีลิงก์ Google Drive แล้ว ให้ใช้ลิงก์ Google Drive เป็นค่าหลักของ `{pdf_url}` และ `{{pdf_url}}` ทั้งใน Facebook (`fb_caption`, `fb_comment`, `fb_comment_2`, `{application_links}`) และปุ่มดาวน์โหลด/Action Buttons บน WordPress
* **FR-4.3:** บน WordPress ยังคงอัปโหลดไฟล์ PDF เข้า WordPress Media เพื่อแสดง `<iframe src="...#toolbar=1&navpanes=0">` ในกล่อง `poster-pdf-viewer-wrap` ตามเดิมไม่เปลี่ยนแปลง แต่ปุ่มลิงก์เปิด/ดาวน์โหลดเอกสารจะชี้ไปยังลิงก์ Google Drive เป็นหลักเมื่อมีลิงก์ Drive

### 5.5 โมดูลสารบัญประกาศ (Standalone Drive Archive & Directory)
* **FR-5.1:** เพิ่มหน้า `สารบัญประกาศ (Drive)` (`/announcements`) ในเมนูหลัก สำหรับ:
  * อัปโหลดไฟล์ PDF เก็บเข้า Google Drive ตามหมวดหมู่และสูตรตั้งชื่อโดยไม่ต้องสร้างโพสต์โซเชียล
  * ค้นหาและกรองประกาศย้อนหลังตามคำค้นหา, ประเภทพนักงาน, ขั้นตอน, ปี/เดือน และสถานะการซิงก์
  * คัดลอกลิงก์ Google Drive ในคลิกเดียว, เปิดดูไฟล์บน Google Drive, กดซิงก์ซ้ำหากเคยล้มเหลว หรือกด `"นำไปสร้างโพสต์ข่าว"` เพื่อส่งไฟล์และข้อมูลหมวดหมู่เข้าสู่หน้า `Posts > Create` ทันที

## 6. Acceptance Criteria

- [ ] **AC-01:** หน้า `Settings > Integrations` สามารถบันทึก Client ID, Client Secret (เข้ารหัสใน DB), Root Folder URL/ID, ทำ OAuth 2.0 เชื่อมต่อบัญชี Google, ตรวจสอบ Health Check และตรวจสอบ/สร้างโฟลเดอร์ย่อยทั้ง 12 โฟลเดอร์ได้โดยไม่เปิดเผยข้อมูลลับใน Inertia Props หรือ Logs
- [ ] **AC-02:** ระบบสร้างชื่อไฟล์ตรงตามรูปแบบ `YYYY-MM-DD {ขั้นตอน}-{ประเภทพนักงาน}-{รายละเอียด}.pdf` (เช่น `2026-10-26 รับสมัคร-รายวัน-แม่บ้าน.pdf`) และรองรับการแก้ไขชื่อเองก่อนอัปโหลด
- [ ] **AC-03:** สามารถแนบไฟล์ PDF และซิงก์ขึ้น Google Drive ได้แม้เลือกช่องทางเผยแพร่เป็น **Facebook เพียงอย่างเดียว** (โดยที่ระบบยังคงป้องกันไม่ให้นำไฟล์ PDF ไปใส่ในช่องรูปภาพหลัก `featured_image` ของ Facebook ตามกฎเดิม)
- [ ] **AC-04:** เมื่อเผยแพร่โพสต์ที่มีไฟล์ประกาศ ระบบอัปโหลดไฟล์เข้าโฟลเดอร์ย่อยที่ถูกต้องใน Google Drive, เปิดสิทธิ์ `anyone: reader`, แทนค่าลิงก์ Google Drive ลงใน Facebook Comment #1 (`fb_comment`), Comment #2 และปุ่มลิงก์บน WordPress อย่างถูกต้อง
- [ ] **AC-05:** บทความบน WordPress ยังคงแสดงกล่อง Embedded PDF Viewer (`<iframe>` จาก WordPress Media URL เดิม) ได้สมบูรณ์ ในขณะที่ปุ่มดาวน์โหลดหลักและ Action Buttons ใช้ลิงก์ Google Drive
- [ ] **AC-06:** การกด Retry ช่องทางที่ล้มเหลวจะไม่อัปโหลดไฟล์ PDF ซ้ำขึ้น Google Drive หาก `drive_file_id` ซิงก์สำเร็จแล้ว
- [ ] **AC-07:** หน้า `สารบัญประกาศ (Drive)` (`/announcements`) สามารถอัปโหลดไฟล์ขึ้น Google Drive แบบไม่ผูกกับโพสต์ ค้นหา/กรองตามประเภทพนักงานและขั้นตอน คัดลอกลิงก์ และกดส่งต่อไปสร้างโพสต์ใหม่ได้
- [ ] **AC-08:** ชุดทดสอบ Feature/Unit Tests ใหม่ทั้งหมดจำลอง Google API ด้วย `Http::fake()` (ไม่มีการยิง API ภายนอกจริงในการรันเทสต์) และชุดทดสอบเดิมของโปรเจกต์ผ่านครบ 100% พร้อมผ่านมาตรฐาน `vendor/bin/pint`
